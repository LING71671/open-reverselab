# Goal 执行

[English](GOALS.md)

每个 Goal 保存目标、任务要求、执行历史、证据和报告。正文与画板展示同一份记录。时间和 Token 限制均可选，留空不会设置整个 Goal 的额度；各工具和网络操作仍有各自的超时。

## 标题与手动命名

规划模型在现有回答中概括简短标题，不单独发起标题请求。完整要求保留在第一条用户消息中。双击任务或按 F2 设置的名称优先，不被模型覆盖。本地哈希核验直接使用操作名称，无需调用模型。

## 运行中补充要求

运行时发送要求会添加一条待处理消息。调度器等待当前流水线步骤结束后再应用；新要求与旧要求冲突时，以较新的为准。目标和 red/blue/both 路线保持不变；分析其他目标需要创建另一个 Goal。

新一轮沿用同一 Goal，读取之前的会话与工具证据，并根据更新后的任务要求建立新的验收条件。旧一轮的回调不能将新目标标为完成。画板节点和报告分别记录不同轮次，保留已有证据。在同一步骤执行期间收到的多条要求会一起应用。

已消耗的时间和 Token 继续计入用户设置的上限，调整任务不会重置额度。停止会取消待执行的后续轮次。重开应用后，中断的运行显示为已停止，不自动恢复执行。

## 证据与路线调整

知识库检索提供参考。没有新匹配文档时，Agent 仍可修正动作或继续观察新证据。同一路线反复遇到相同失败且证据没有变化时，停止重复尝试。

验收计划可以使用 `goal-plan` 代码块、JSON 代码块或回答开头的 JSON 对象，结构校验保持一致。目标和任务要求取自 Goal，不采信模型 JSON 中改写的目标。完成需要真实工具输出及针对固定验收条件的独立核验，仅生成脚本不会标为完成。

## 验证

在仓库根目录执行：

```sh
node --test desktop/src/services/goals/goalManager.test.mjs desktop/src/engine/tests/pipeline.test.mjs
pnpm --dir desktop build
```

测试覆盖隔离、排队、停止、可选额度、调整生效边界、证据保留、标题归属和失败路线恢复。模型服务与桌面集成仍需真实调用验证。
