# 桌面智能体运行时

[English](AGENT_SYSTEM.md) · [架构说明](ARCHITECTURE.zh-CN.md)

Open ReverseLab 围绕目标运行 Goal，由 `red`、`blue` 或 `both` 选择观察、执行动作、保留证据并独立核验结果。时间与 Token 预算可选，用户可以在执行中补充要求或停止 Goal。

本文描述当前契约与实现边界。工具执行成功、报告保存和目标通过核验分别记录。

## 策略契约

| 策略 | 自己拥有的内容 | 共享的内容 |
| --- | --- | --- |
| `red` | 分析假设、验收条件、动作选择与判定规则 | 工具适配器、知识索引、事件契约与运行服务 |
| `blue` | 防御问题、必要观察、检测或修复评估 | 同一组运行服务 |
| `both` | 策略启动、预算分配、证据交换与整体核验 | 同一个 Goal 总预算 |

[red.ts](src/engine/tracks/red.ts) 与 [blue.ts](src/engine/tracks/blue.ts) 分别实现 [TrackPolicy](src/engine/tracks/contract.ts)，[both.ts](src/engine/tracks/both.ts) 组合两方执行器，各自保留上下文、路线历史、动作输出与判定。

两方都可以创建动作分叉与汇合，在执行中交换观察，后续动作也可以依赖对方产生的证据。各自职责通过核验后，还要[核验原始完整目标](src/engine/tracks/verifyBothGoal.ts)。

知识选择依据索引中的 track：red 读取 `kb/red/` 和 `kb/shared/`，blue 读取 `kb/blue/` 和 `kb/shared/`。both 两方分别检索自己的资料，配对文档链接用于定位关联材料，不改变接收方策略。

## Goal 归属与目标修订

[GoalManager](src/services/goals/goalManager.ts) 在提交时复制目标、任务、策略与可选预算。回调绑定 Goal ID，切换当前 Goal、工作区或顶部策略都不会改变执行目标。管理器始终保留在原[工作区运行时](src/services/goals/workspaceRuntime.ts)中。

模型与提供商配置在每次 pipeline 开始执行时复制，因此排队任务使用实际启动时的配置；both 两方继承同一快照。修改设置不会替换正在进行的模型请求。

运行或排队中的 Goal 可通过 `steer` 接收补充要求：

1. 将带序号的修订追加到目标，保留用户消息并标记为 `pending`。
2. 等当前阶段结束，动作 DAG 在启动后续动作前检查是否有修订。
3. 拒绝旧目标的完成判定与过时产物。
4. 沿用 Goal ID，将修订加入队列，保留正文与选取的先前工具证据。
5. 使用剩余总预算启动，将对应修订标记为 `applied`；新节点与报告命名空间区分不同修订。

停止操作同时取消待应用修订和当前执行。已取消或已结束执行的晚到回调不能修改最终记录。取消排队任务不会调用执行器；取消运行任务会发送信号，直到执行器结束才释放运行名额。

## 规划与动作 DAG

[HarnessPipeline](src/engine/pipeline/HarnessPipeline.ts) 编排目标发现、初筛、知识检索、模型规划以及执行与核验。核验失败可携带失败原因和下一假设返回检索与规划；没有新的知识库匹配本身不代表观察路线耗尽。

规划可返回验收计划，以及包含以下字段的 `action-plan`：

| 字段 | 含义 |
| --- | --- |
| `id` | 本轮唯一动作 ID |
| `title` | 可读动作标题 |
| `dependsOn` | 前置动作 ID |
| `script` | 该动作的 Python 源码 |

[actionPlan.ts](src/engine/pipeline/actionPlan.ts) 在执行工具前校验完整图，拒绝重复 ID、缺失依赖、环与格式错误的显式计划。无效的显式 DAG 不会降级为单脚本执行；没有显式动作计划时，仍兼容已有的单 Python 脚本响应。

就绪动作并发运行。启动时，脚本获得包含父节点结果的 `REVERSELAB_INPUTS`，以及包含当时对方消息的 `REVERSELAB_PEER_EVIDENCE`。运行时记录实际输入绑定和脚本，供后续核验。成功动作的 stdout 注册为 `actions.read.stdout` 等证据来源，工具记录保留输出与耗时。

每个调度器的 DAG 创建后保持不变。后续规划创建新 DAG 和新画板节点 ID，保留此前尝试。画板宽度由实际独立动作与依赖决定。

### 调度与取消

[DagScheduler](src/engine/runtime/dagScheduler.ts) 支持任意有限无环图。GoalManager 与调度器默认不设并发数量上限，嵌入方可以显式注入上限。每个节点在一次调度中至多运行一次。

| 依赖策略 | 就绪条件 | 用途 |
| --- | --- | --- |
| `allSucceeded` | 所有父节点成功 | 需要前置产物的动作 |
| `allSettled` | 所有父节点进入终态 | 同时处理成功、失败与取消的汇合 |

必需前置动作失败会取消其普通后代，无关动作继续。`allSettled` 汇合接收所有直接父节点的结果。分支取消沿普通后代传播，在这类汇合处停止；全局取消覆盖整张 DAG。

节点状态为 `queued`、`running`、`succeeded`、`failed`、`cancelled`。发出取消信号不代表进程已经停止；执行器实际返回或抛错前，运行名额与资源归属继续保留。观察者异常与工具失败分别记录。

调度器支持互斥 `resourceKeys` 和注入的 `DagResourcePool`，共享同一个池可以跨调度器串行访问资源。当前生成动作的 schema 不提供资源 key，也未接入工作区级共享池；设备与调试器适配器需要互斥时须接入这些能力。锁作用于当前进程，不提供跨进程互斥。

## 证据交接与重复检测

[AgentMessageBus](src/engine/runtime/agentMessages.ts) 在同一 Goal 已登记的 Agent 之间路由消息，携带发送者、接收者、类型、可选关联 ID 与证据引用。类型包括 `evidence`、`question`、`answer`、`blocked`、`result`。已接受消息的内容复制并冻结，重复 ID 不重新投递。

both 发布动作观察、知识引用、阻塞原因和分支结果。规划阶段读取对方消息，动作启动时读取已经收到的对方观察。证据节点引用形成画板交叉连线。相同指纹的动作可以在同一次 both 运行中共享执行 Promise，两方仍分别判断输出。

动作指纹包含目标、脚本、父节点观察和对方观察。[观察标识](src/engine/pipeline/observationIdentity.ts) 统一 JSON 键顺序，并排除对方消息中的投递 ID、画板节点 ID 和执行耗时。同一脚本与输入不会仅因改选知识文档而重新执行；单脚本计划还会规范化注释与空行，用于重复检测。

路线账本比较失败类别、观察指纹与所选资料。同一路线重复出现不变失败时结束该循环；不同候选路线出现相似症状时保留告警，并允许继续其他候选。新文档、时间戳或改写总结本身不构成进展证据。

当前机制按输入检测重复，不做程序语义等价分析。内容不同但等价的程序仍可能绕过精确比较，通用目标版本与证据新鲜度跟踪尚未完善。

## 独立目标核验

| 结果 | 记录的含义 |
| --- | --- |
| 工具执行成功 | 进程或适配器正常完成 |
| 证据可接受 | 观察满足策略的证据检查 |
| 目标经过核验 | 固定的验收条件通过独立评估 |

[goalVerifier.ts](src/engine/pipeline/goalVerifier.ts) 在执行前将首份有效验收计划绑定到当前目标与任务。每个检查包含 `id`、`criterion`、`expected`，后续路线保留这份计划。用户修订会为新目标建立新计划。

明确的 SHA256 目标使用确定性路径，将观察结果与独立初筛数据比对。其他目标通过单独模型请求评估原目标、固定检查、实际执行程序及输入绑定、工具证据，返回 `verified` 或 `continue`，附逐项观察与证据原文。模型评估标记为 `model_assessed`。

运行时要求返回的检查 ID 与计划完全对应。通过项必须引用给定证据键，并逐字引用该来源中存在的文字。缺项、虚构引用、缺少原文或目标覆盖不全会保持未核验状态，并反馈缺口供后续规划使用。脚本自己输出的 `passed: true` 不是完成信号。

核验模型同时评估引用证据与采集程序，并将目标内容、知识正文和 stdout 作为数据处理。这些输入不能改变已绑定的目标与验收计划。原文检查能够确认给定输出中的来源，模型的语义判断仍需要相应的真实任务验收。

both 的分支判定保留各自职责。整体核验给两方的检查 ID 和证据 ID 加前缀，检查完整目标覆盖情况，一方成功不能代替另一方。

## 预算与终态

`maxDurationMs` 和 `maxTokens` 是独立可选字段；未设置表示没有总上限，持久化请求预算时省略。没有有限剩余额度时，模型请求不附加输出 Token 或请求总时限。

Pipeline 使用单调时钟控制截止时间。设置总时限后，请求与动作接收剩余时间；目标修订扣除先前耗时与 Token 消耗，切换路线不重置用量。

初筛和 Python 执行默认不设工具时限；设置 Goal 时限时，桥接层传递有限的剩余时间，否则省略超时参数。已耗尽的时长会在派发前拒绝执行。原生应用和浏览器开发执行在取消或到期时都会终止 Python 子进程树。工具传输保留输出，不设置默认 4 MiB 截断或缓冲区终止限制。

Token 统计包含规划与独立核验。提供方返回 usage 时使用实际用量，否则标明估算。缺少完整 usage 和精确输入计数时，用户设置的 Token 预算只能按估算控制。

both 设置有限 Token 预算时，协调器为整体核验预留至多三分之一，最高 8,192 tokens；其余由 red、blue 分配，奇数余量给 blue。一方结束后，另一方可通过协调器使用它未花费的额度。最终检查包含两方总用量；不限预算和内置哈希路径不做这项预留。

`RunProgress` 实际使用以下状态：

| 状态 | 含义 |
| --- | --- |
| `running` | 正在执行，也包括交接到待应用的目标修订 |
| `completed` | 当前目标通过必要核验 |
| `exhausted` | 设置的时间或 Token 预算耗尽 |
| `blocked` | 必要能力、证据、可行路线或有效输出不可用 |
| `cancelled` | 用户停止运行 |

原因与健康错误码进一步区分预算耗尽、服务不可用、重复失败等情况。摘要检查点保留目标、任务、策略、已访问资料、动作指纹与阻塞原因；它不序列化活动进程，也不提供应用重启后的自动续跑。

## 事件、界面与诊断

回调发送步骤、工具记录、阶段诊断、交付物、运行进展与[健康事件](src/core/contracts/health.ts)。健康事件标明 Goal、分支、Agent、节点、状态、错误码与可选耗时。[HealthMonitor](src/services/health/healthMonitor.ts) 汇总保留的观察，同一 trace 的恢复不会抹掉另一 trace 的失败，未观测层保持 `unknown`。

正文展示分析进展，计划、脚本、输出和核验明细按需展开。画板使用真实依赖与证据连线，保留失败尝试及后续路线；界面不会根据节点数量或报告存在与否推断成功。

工作区运行时将新接收的健康事件发送给可选诊断接收器，历史恢复与界面渲染保持本地处理。用户开启后，Sentry 才发送脱敏错误和采样耗时；关闭会取消在途发送。原生性能提醒使用独立后台采样器。详见[诊断说明](DIAGNOSTICS.zh-CN.md)。

## 当前实现边界

- 直接执行适配器提供目标初筛与 Python 进程；脚本可使用当前用户权限调用已安装库和命令行工具。专用调试会话、设备控制和加固适配器仍需接入同样的执行与取消契约。
- Agent 消息总线当前默认保留 128 条历史、每个收件箱 64 条消息，每个总线接收至多 512 条消息，关联回复至多 8 跳。这些值可通过总线 API 配置，不是 Goal 或动作并发上限。
- 模型证据输入使用摘录：独立核验当前在各 stdout 来源之间分配总计 16,000 字符。完整工具记录和保存的脚本与核验器选取的输入用途不同。
- 动态规划发生在 DAG 执行之间，界面尚未提供任意活动图编辑或任意 Agent 角色创建。
- 运行快照恢复历史与中断状态，不恢复活动执行。通用证据新鲜度、语义级动作去重与跨工具假设搜索尚未完整实现。
- BLA / REA 配置定义验收工作，尚不声明已完成上游对抗实测，详见 [ADVERSARIAL_PROFILES.md](ADVERSARIAL_PROFILES.md)。

## 修改运行时后的验证

沿用[开发检查](DEV_GUIDE.zh-CN.md)，覆盖改动实际影响的行为：

- 并发 Goal 与动作分叉保持隔离，取消一个任务不影响无关工作。
- 无效 DAG 不启动工具；汇合接收所有父节点结果；取消未结束时继续持有资源锁。
- both 保留分支核验、跨策略证据与统一预算。
- 修订保留历史与已用预算，旧结果不能完成新目标。
- 重复动作、不变失败、格式错误的计划、自报成功与无依据证据不能静默通过。
- 模型、知识库、工具和存储故障可以区分，缺失 usage 时标明估算。
- 报告保留工作区归属，恢复的中断任务仍然标记为中断。
- 代理取消与失败切换保留请求语义；可选诊断不补传历史，关闭后不再继续发送。
