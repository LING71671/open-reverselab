# Open ReverseLab 桌面端

[English](README.md)

Open ReverseLab 围绕目标创建 Goal，通过实时流程画板、可读的分析进展和执行证据组织任务。选择 `red / blue / both`，填写文件、目录或 URL，再描述需要完成的结果。

本文对应当前桌面源码预览。公开下载及其支持的功能以 [Releases](https://github.com/LING71671/open-reverselab/releases) 为准；源码中的版本号不代表对应安装包已经发布。

## 从源码启动

在 `desktop/` 目录运行：

```sh
pnpm install --frozen-lockfile
pnpm dev
```

原生桌面使用 `pnpm tauri dev`。Python 3.10+ 需要能通过 `python` 调用；原生构建还需要 Rust 和 [Tauri 平台工具链](https://v2.tauri.app/start/prerequisites/)，Windows 运行时需要 WebView2。分析工具单独安装。浏览器预览通过本机开发服务读写工作区、执行 Python；原生代理路由、进程监测与应用内安装需要桌面应用。

可用 `REVERSELAB_ROOT` 指向包含知识库和脚本的仓库。构建与检查命令见[开发指南](DEV_GUIDE.md)。

## 创建 Goal

1. 点击工作区名称，打开或新建工作区。首次启动会在应用与仓库目录之外创建默认工作区。
2. 打开 **设置 → 模型**，填写兼容 chat-completions 的 API 地址、API Key 和模型 ID 后保存。可以读取提供商的模型列表，也可以直接填写 ID。“保存并测试”会向该提供商发送一条短请求。
3. 在左上角选择 `red / blue / both`，分别填写“目标”和“Goal”。从“样本”导入文件或目录会保留原件副本并创建工作副本；直接填写外部路径则使用该路径。
4. 开始任务。时间与 Token 上限默认留空，按需填写；Goal 和就绪动作的并发数量默认不设上限。

模型来自已保存的配置或明确设置的 `VITE_LLM_MODEL`。配置缺失时不会代选提供商或模型。基础 SHA256 核验可以通过本地确定性检查完成；其他 Goal 使用所选模型规划动作，并独立评估执行证据。

运行中可在输入区发送补充要求或调整目标，沿用同一个 Goal。要求先显示为待生效，当前步骤结束后应用；历史与已有证据继续保留，修订后的目标需要重新通过核验。“停止”会取消运行并保留已记录的进展。

可以在任务运行时创建其他 Goal 或切换工作区，每个执行器始终归属于启动它的工作区。模型会生成简短任务标题；双击标题或选中任务后按 **F2** 可以重命名，手动标题优先保留。

## 阅读进展与证据

“正文”展示 Agent 的分析进展与结论。计划、脚本、结构化数据、工具输出和核验明细按需展开，结果中保留报告路径。

“画板”展示实际动作、依赖、证据交接和汇合关系。点击卡片展开详情或查看执行记录；拖动画布、缩放查看分支，点击“跟随流程”跟进当前任务。画板支持全屏，按 **Esc** 退出。手动浏览后会关闭跟随，需要时可以重新开启。

`red` 与 `blue` 使用各自的策略和知识路径。`both` 中，两方可以并行安排动作、相互传递证据，画板呈现相应交叉连线。各分支分别核验后，再核验完整目标。

知识库按 [`kb/red/`](../kb/red)、[`kb/blue/`](../kb/blue) 和 [`kb/shared/`](../kb/shared) 分开。red 读取攻击网，blue 读取防御网，两方均可检索共享资料。知识库页面读取真实索引，并关联配对文章。

健康监控按 Goal、Agent、模型、知识库、工具和存储汇总已观测事件，没有观测的服务保持未知。当前直接执行适配器提供目标初筛和 Python 执行，脚本可调用已安装的库与命令行工具；专用调试器、设备控制及加固适配器需要另行接入。BLA / REA 验收安排见[对抗验证计划](ADVERSARIAL_PROFILES.md)。

## 设置

设置使用整页布局，包含工作区、模型、代理池、诊断、本机工具和应用更新。“返回工作区”恢复工作区视图。

- [代理池](NETWORK.zh-CN.md)：独立配置模型请求与 Python 目标访问，支持命名节点、认证、连接测试和模型请求的失败切换。
- [诊断](DIAGNOSTICS.zh-CN.md)：可选的后台性能异常提醒，以及可选的 Sentry 错误和耗时上报，两项默认关闭。
- [应用更新](UPDATES.md)：检查版本、查看下载进度及签名验证结果；支持应用内升级的安装版需等待所有已打开工作区的运行与排队任务结束后安装。

## 工作区与数据

Goal、报告、脚本和导入的样本保存在工作区的 `.reverselab/` 中。迁移工作区或升级安装版前备份该目录，并将工作区与程序文件分开存放。恢复历史不会重新启动已中断的外部进程，也不会重定位绝对目标路径。存储规则见[工作区说明](WORKSPACES.md)。

API Key 和代理凭据保存在本机 WebView 存储中，尚未接入系统密钥库。模型辅助任务会把任务上下文与所选证据发送给配置的端点，Python 动作使用当前用户权限。草稿与阅读位置在本次工作区会话的页面切换间保留。

本地开发可以通过 `VITE_LLM_BASE_URL`、`VITE_LLM_API_KEY` 和 `VITE_LLM_MODEL` 初始化配置。Vite 会把 `VITE_*` 值写入前端构建，私人密钥不得进入分发构建或公开提交。

Open ReverseLab 用于合法授权范围内的分析，请阅读[免责声明](../DISCLAIMER.zh.md)。私人样本、目标、报告、凭据和本机截图不进入公开提交。
