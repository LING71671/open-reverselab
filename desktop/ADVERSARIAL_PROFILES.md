# BLA / REA 对抗能力

## 已确认的设计目标

用户指定 red 抵抗 BLA 类分析干扰，blue 评估与降低 REA 类分析能力对自有软件的暴露风险。2026-11-13 核对官方仓库：[qybaihe/bla](https://github.com/qybaihe/bla)、[morluto/rea](https://github.com/morluto/rea)。

BLA 的项目说明包括诱饵、伪造元数据和分析资源消耗。REA 的说明包括程序产物与运行行为分析，以及供 Agent 使用的工具接口。以上是上游描述；本项目尚未安装、执行这两个上游工具进行对抗验收。下表是本产品的设计与测试要求。

## 策略分工

| 策略 | 保护对象 | 需要验证的结果 |
| --- | --- | --- |
| red | 分析 Agent 的目标、判断和运行预算 | 不采信样本中的角色/命令，不把诱饵当结论；遇到无效路线能有界退出并寻找其他证据 |
| blue | 自有软件的敏感信息、关键逻辑与合法运行行为 | 明确发布暴露面，实施控制后以同条件复测，并保持原功能 |
| both | 同一 target 的分析与防御证据 | 两条独立分支交接证据，保留冲突与失败；共同完成才标为完成 |

red 的防误导规则也适用于 blue 读取目标与工具输出。blue 的防御测试不能只用某个工具崩溃、一次超时或 Token 估算证明成功。发布包中的字符串、符号、source map、IPC 与协议只是待评估的观察面，具体暴露需要实际证据。

## 分层防护

- 输入资料保留来源和目标身份，样本、KB 正文、工具输出及 Agent 消息都不能改变原目标或预算。
- 分析过程限制时间、上下文大小、单次工具运行时长、重复动作与消息总量。截断应记录范围，后续改用局部观察。
- 路线账本记录失败原因、动作指纹和证据变化；重复失败不继续执行同一脚本。
- 判定先固定验收计划，再对实际工具输出独立核验。字符串匹配只证明字符串存在，业务结论需要对应观测。
- blue 的修改要作用于工作副本，并配套功能回归、性能对照和可恢复产物。目前桌面适配器执行观察，自动加固执行器仍待接入。

## 验收矩阵

| 场景 | 合成用例 / 上游样本 | 断言 |
| --- | --- | --- |
| 提示污染 | 样本字符串包含伪系统指令 | target、策略与验收条件保持不变 |
| 伪证据 | 假密钥、错误符号或无关输出 | 无对应实际观测时不能完成 Goal |
| 资源膨胀 | 大量候选项、长输出、嵌套数据 | 单步有界，显示截断或预算原因 |
| 路线绕圈 | 同脚本、同失败、同观察结果 | 去重并留下路线记录 |
| 通讯污染 | 跨 Goal 消息、重复 ID、循环回复 | 隔离、去重、跳数与消息量限制 |
| 防御有效性 | 相同基线与加固产物的提取任务 | 比较敏感信息暴露与任务达成情况，记录时间和 Token |
| 功能等价 | 加固前后同输入测试集 | 保留行为，记录差异与性能代价 |
| 部分成功 | red 或 blue 失败 | 合流保留两方证据，整体不能误报成功 |

已有测试覆盖任务隔离、DAG 合流、消息限制、脚本去重、预算与证据引用检查。上游 BLA/REA 的具体版本、样本哈希、模型、环境与测试结果必须另行保存到私有工作区；这些实测尚未完成。当前不应出现“已防住 BLA / REA”的产品声明。
