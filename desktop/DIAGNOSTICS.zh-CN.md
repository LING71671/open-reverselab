# 诊断

[English](DIAGNOSTICS.md) · [桌面使用指南](README.zh-CN.md)

**设置 → 诊断** 包含“性能异常提醒”和“发送诊断数据”两个独立开关，默认均关闭。偏好保存在本机，切换工作区后继续使用。

## 性能异常提醒

在桌面应用中开启“性能异常提醒”，可检测持续卡顿或资源占用异常。正常运行时不占用常驻状态栏；观测到异常持续后才显示提醒，也不会停止 Goal 或减少并发任务数。

[diagnostics.config.json](diagnostics.config.json) 中的默认策略约每两秒采样一次，异常至少持续 15 秒后提醒：

| 异常 | 阈值 |
| --- | --- |
| CPU 持续高负载 | 可用逻辑核心总量的 90% |
| 内存持续偏高 | 进程工作集总量达到 2 GiB |
| 界面持续响应缓慢 | 连续采样区间内出现至少 250 ms 的动画帧间隔 |

CPU 与内存范围包括 Open ReverseLab 及其 WebView、Python 等子进程。CPU 需要两次观测才有百分比；内存汇总可能重复计算共享页。动画帧间隔用于观测界面响应情况。

“关闭此提醒”隐藏当前异常，恢复正常后才会再次针对同类异常提醒，监测仍然运行。隐藏窗口时暂停采样并清除当前提醒，显示窗口后重新观测。关闭设置开关会取消定时器与动画帧回调，释放原生采样器。CPU、内存与帧间隔采样值不存盘、不上传；浏览器预览不采集原生进程数据。

## 远程错误与耗时上报

构建配置了有效的 `VITE_SENTRY_DSN` 后，可以开启“发送诊断数据”向 Sentry 上报。未配置诊断端点的构建中，该开关不可用。开启远程诊断不会同时开启本地性能监测。

仅开关开启后的新运行事件进入上报流程。打开历史 Goal 或重新汇总其健康状态不会补传历史记录。上报字段如下：

| 类型 | 包含的数据 |
| --- | --- |
| 运行失败 | 已定义的错误码及其所属层，如模型、工具或存储 |
| 未处理的界面错误 | `UI_UNHANDLED`、标准错误类型，以及仅指向应用构建资源的堆栈位置 |
| 操作耗时 | `operation.tool` 等通用层名称、耗时、状态及生成的追踪标识 |
| 公共信息 | 应用版本、构建环境、事件标识与时间 |

脱敏处理会移除样本、目标、提示词、文件路径、凭据、错误原文、工具输出、用户信息和其他任意事件字段。IP 推断已禁用，并通过空地区字段阻止服务端补充地区信息。自动会话回放、面包屑记录与请求监测均关闭。

操作耗时默认采样 10%，由 [diagnostics.config.json](diagnostics.config.json) 的 `remote.traceSampleRate` 定义。设为 `0` 会关闭耗时上报；用户开启诊断时仍可上报错误。

关闭“发送诊断数据”会移除事件监听、断开运行事件接收器、关闭 SDK，并取消在途上报。已被接收的事件仍保留在配置的 Sentry 项目中。诊断发送失败不会中断 Goal。[代理池](NETWORK.zh-CN.md) 管理模型与 Python 路由，Sentry 使用 WebView 自身的网络配置。

## 构建配置与检查

需要提供远程诊断的发行构建，通过 `VITE_SENTRY_DSN` 配置项目的公开接收 DSN。Sentry 管理令牌与认证令牌不得写入 `VITE_*` 或前端代码。保持 `remote.enabled` 为 false，由用户自行开启。

本地[诊断策略测试](tests/diagnostics.test.ts)覆盖默认值、持续异常、偏好处理与历史事件隔离；[SDK 传输测试](tests/telemetryTransport.test.mjs)使用已安装的 Sentry SDK 和合成传输，检查实际序列化数据、脱敏、取消与开关竞态。真实项目送达及服务端保存字段需要针对构建配置的诊断端点单独检查。
